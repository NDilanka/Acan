# The go bar

Acan implementation starts only when every line below is green. Each line names how it is checked, so "perfect" means the same thing to every reviewer. The status column is updated after each round. A line goes back to red when a later change breaks it.

| # | Line | How it is checked | Status |
|---|---|---|---|
| G1 | **One journey.** The core loop runs as one continuous session in one shell. Intent, pins, order, readbacks, claim, declarations, clash, settle, gate, bench, then publish or hold, and the world canvas around it. No hash switching or reloads, and no fixture seams a user can see. | `journey.steps.json` drives the whole loop by keyboard and again by mouse, and it ends `OK`. | red, no journey shell yet |
| G2 | **Every state passes.** Each concept and the journey pass their steps in dark and light, and in every `kv` script. Loaded but inactive, they change nothing. | `drive.mjs` prints `OK` for every steps file and every appearance, with no page errors. The all-concepts build with no hash still runs ui-v1 modes 1 to 4. | amber, light covered only by boot checks on some concepts |
| G3 | **The quality bar is enforced by a machine.** No visible text below 11 px. No two labels overlap. No card leaves the viewport. Body text meets WCAG AA contrast (4.5:1), and large text 3:1, in both appearances. Every focusable control shows a visible focus ring. There are no CSS transitions except camera easing and ink-in. Focus never moves without input. | `audit.mjs` runs at every `shot` and fails the run on any finding. | red, the audit does not exist yet |
| G4 | **Honest evidence.** Every number on screen comes from the fixture. The five evidence states look different from each other. The egress pill total equals the sum of the network log. Every agent claim shows its source. | Audit checks the pill sum and the evidence state classes. A reviewer checks the fixture trace. | amber, the polish pass is fixing the pill on gate |
| G5 | **Cross-lab ready verdict.** One Anthropic reviewer and one reviewer from another lab each return "ready, no must-fix" on the journey, which hosts world and all four core concepts. Standalone concepts are scaffolding, so their critique findings feed the journey build rather than separate polish rounds. | `review/journey-<lab>-rN.md` | red, the journey is not built; world r2 and core4 r2 findings feed it |
| G6 | **First use works cold.** Fresh agents with no context, given only the screen and a one-line task, finish the core tasks. The tasks are: post an order from two witnesses, answer the readback question, settle both clashes, decide the gate, pick on the bench, and find the plant that blocks publication. Each agent drives with keys and clicks only. | `cold/` reports. At least 5 of the 6 tasks succeed for each of two models. No task needs more than twice the expert step count. Every failure becomes a fix. | red, not run |
| G7 | **The map agrees.** `proposals/ui-v2.md` matches what the prototypes prove, including the same-file decision. Every rewritten map row points to a prototype beat or a research finding. | Reviewer diff of the proposal against the prototypes. | amber, the prototype section is stale |
| G8 | **The user signs off.** The user clicks through the journey and the concepts in a browser and says go. | The user. | red |
| G9 | **One shell, little text.** Every level and concept uses the floating-island shell in `SHELL.md`, the layout the user picked (`shots/orders-kv-unmatched.png`). Visible words per surface and per screen stay within the budgets in `TEXT.md`. | Audit word-count and island-position rules on every shot, plus the user's eye. | red, SHELL.md and TEXT.md in progress |

## Process

Each round goes critique, then a fresh fix round, then my own rerun of every steps file and a look at key shots. The status column changes only on evidence I reran myself. When G1 to G7 and G9 are green, I open the journey in a browser for G8 and give the go signal only after the user's yes.
