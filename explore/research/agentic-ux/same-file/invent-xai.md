# Same-file co-editing. Three mechanisms, one pick.

## What is being invented, and what is not

[sourced] Text convergence does not imply correct code. CodeCRDT reports both convergence and semantic conflicts (`m1-prior-art.md:5`, https://arxiv.org/html/2510.18893). [sourced] Agents do not edit by keystroke. Claude Code replaces an exact string (`m3-agent-collisions.md:16`). Codex applies a contextual patch (`m3-agent-collisions.md:28`). Droid's public pages do not specify a matching algorithm, so Orrery must record the installed harness (`m3-agent-collisions.md:34-36`). [inferred] A shared buffer that the harness never writes into is not co-editing. It is a second editor the agents ignore.

[inferred] The taxonomy in `m3-agent-collisions.md:100-109` is the routing table. None of the mechanisms below covers every row. Independent registry, import, and barrel additions go to keyed contributions or a split (`m3-agent-collisions.md:102`, `m3-agent-collisions.md:115`). Ordered routes stay sequential micro-turns (`m3-agent-collisions.md:103`). Two agents rewriting one algorithm stay one implementer and one reviewer (`m3-agent-collisions.md:106`). Cross-file coupling stays a contract split settled on the belt before code (`CORE.md:15`, `m3-agent-collisions.md:107`). Lockfiles and generated outputs stay one producer (`m3-agent-collisions.md:108`). Migrations stay one ordering owner (`m3-agent-collisions.md:109`).

[inferred] What remains is the exception the taxonomy already names. Disjoint work inside a cohesive file (`m3-agent-collisions.md:104`). Independent syntax on one line that line merge cannot see (`m3-agent-collisions.md:105`, `m3-agent-collisions.md:60`). And the publication race that drops an update even when the edits would have composed (`m3-agent-collisions.md:42-44`). [sourced] Kvarm already merges non-overlapping line changes (`m2-kvarm-hooks.md:5`, `m2-kvarm-hooks.md:25`) and warns only at path or prefix granularity (`m2-kvarm-hooks.md:6`, `m2-kvarm-hooks.md:46-47`). The gap is not whether git can merge two commits. The gap is a cross-harness transaction that accepts a string replace, a patch, or a whole-file write against the blob the agent read, and that refuses a tree whose checks name any other sha (`m1-prior-art.md:9`, `m1-prior-art.md:169-171`, `m2-kvarm-hooks.md:82-83`).

[inferred] Kvarm owns coordination. Orrery owns the drawing, the witnesses, and the readbacks (`01-synthesis-wave3.md:7`). There is no second coordinator (`01-synthesis-wave3.md:18`). A same-file session is a narrowing of a clash, not a way around it (`m3-agent-collisions.md:121`).

## Mechanism A. Stencil

**Pitch.** A file several agents must extend becomes a named collection of keyed contributions, not a shared buffer. Each agent writes only its own contribution file. One integrator, which no agent is, folds accepted contributions into the published source. The shared file is a projection. Agents never hold its bytes.

**Data shape.** Name the object before the protocol. A `Stencil` is `{stencilId, path, baseBlob, revision, grammarId, slotId, keyField, integratorPrincipal, state}`. A `Contribution` is `{contributionId, stencilId, key, owner, generation, baseRevision, payloadBlob, payloadHash, state}`. The unit of coordination is the key inside a slot, not a line. The anchor is the key, which survives line drift because the contribution never lives at a line. `revision` is the published projection's blob. `owner` and `generation` are the fencing pair on that key, reused from `fenced_claims` (`m2-kvarm-hooks.md:70`, `m2-kvarm-hooks.md:78`). State on the stencil is `open`, `folding`, `published`, `conflicted`. State on a contribution is `proposed`, `held`, `accepted`, `rejected`, `superseded`.

**Protocol.** A prior settlement posts the stencil. Kvarm logs `record_decision` (`CORE.md:89`). The agent calls `forecast`, sees the stencil rather than a free path (`m2-kvarm-hooks.md:19`), and claims the key with `claim_task`, fenced by owner and generation (`m2-kvarm-hooks.md:78`). A second claim on that key is rejected. That is the atomic step (`01-synthesis-wave3.md:8`). The agent writes a contribution file under a reserved prefix with its ordinary Write or ApplyPatch (`m3-agent-collisions.md:16`, `m3-agent-collisions.md:28`). It does not edit the published source. Kvarm accepts the commit only if the payload parses, the key matches the claim, and the hash matches the blob. A pinned runner on the `ci` credential folds accepted contributions and opens one change (`01-synthesis-wave3.md:32`). Exact-tree checks run on that fold (`m2-kvarm-hooks.md:27`). A duplicate key stays `held` and a clash pin appears. A stale claim is rejected (`m2-kvarm-hooks.md:78`). On crash the lease expires and the file stays unaccepted until a new generation claims the key. Offline, the write may land locally, but publication waits (`CORE.md:84`).

**Safety.** [inferred] The published file changes only when the integrator runs, so two agents cannot clobber each other. Behavior is checked by the witnesses already locked on the order, which agents cannot rewrite (`CORE.md:12`, `01-synthesis-wave3.md:9`). [inferred] This cannot guarantee that two legal contributions compose. A route key and a middleware key can each parse and still double-charge. That remainder is the taxonomy's leftover (`m3-agent-collisions.md:102`). The fold is refused, not silently unioned. Git's union driver can emit both sides in arbitrary order, so union is not the fold (`m3-agent-collisions.md:111`).

**Plant.** The file is a tray of keyed plates on the owning machine, not a buffer. Each plate shows owner, generation, and state from one binding (`CORE.md:93`). A held duplicate is a brass pin. Shift 1 accepts. Shift 2 rejects. Shift 3 sends it back to a contract split. I jumps to the next pin. V toggles footprints. An arrival never steals focus (`CORE.md:27`, `CORE.md:32`). One key, under ten seconds.

**Cost and slice.** [guess] About two weeks. Kvarm adds a stencil table, a prefix check, and a fold that reuses `compose_candidates` path selection (`m2-kvarm-hooks.md:33-35`). Orrery adds the tray and the pin. The slice is one grammar on one repo, an import block or a route table. Kill predicate. Twenty disjoint additions publish with locked checks green. Five duplicate keys stay `held` and never touch the published path. A key that does not match its claim is rejected. If agents still edit the published path, or a duplicate folds, the mechanism is dead.

**Serves.** Registry, import, and barrel additions, when a key exists (`m3-agent-collisions.md:102`). **Routes elsewhere.** Same-line syntax with no key, disjoint functions that are not slots, and any competing algorithm.

## Mechanism B. Loom

**Pitch.** Each agent keeps its own workspace and its own tools. Nobody shares a writable checkout. Each edit is admitted against the blob the agent read. Kvarm weaves admitted edits into one candidate tree, runs the locked checks on that tree, and publishes only that tree. The shared file is a weave, not a live buffer.

**Data shape.** Name it `Loom`. A `Loom` is `{loomId, path, baseBlob, baseCommit, witnessSetId, treeSha, state}`. A `Strand` is `{strandId, loomId, owner, generation, readBlob, readCommit, tool, anchor, edit, resultBlob, state}`. The unit of coordination is the strand, one admitted edit. The anchor is not a line number. It is `{kind, text, occurrence, treePath}`. `kind` is `exact` for a string replace, `context` for a patch hunk, or `span` for a whole-file write. `text` is the old string or the patch context, taken from `readBlob`. `occurrence` is the match index in that blob. `treePath` is optional and filled only when a bounded parse succeeds. [sourced] Yjs relative positions survive concurrent edits inside a CRDT (`m1-prior-art.md:28`). A strand anchor is the same idea for a tool call that already happened against a known blob, so it does not need a character CRDT. `readBlob` is the revision the reasoning used. `owner` and `generation` fence the strand. State on the loom is `open`, `weaving`, `checking`, `published`, `conflicted`, `stale`. State on a strand is `admitted`, `applied`, `conflicted`, `withdrawn`, `stale`.

**Protocol.** The agent reads through Kvarm, or Orrery records the blob hash of the harness read. That hash is `readBlob`. The agent then edits with its existing tool, in its own workspace (`m3-agent-collisions.md:16`, `m3-agent-collisions.md:28`, `m3-agent-collisions.md:36`). Before the push may publish, a thin MCP call admits the strand. `set_intent` may carry an advisory region. The region is not the lock (`m2-kvarm-hooks.md:18`, `m2-kvarm-hooks.md:112`). Admission sends `{readBlob, tool, anchor, edit}`. Kvarm checks that `anchor.text` occurs in `readBlob` at `occurrence`, then replays the edit onto the current blob if the head moved. A unique replay stores `resultBlob` and marks the strand `applied`. A failed or ambiguous replay marks it `stale` and returns the blob plus the anchor that moved (`m1-prior-art.md:175`). The agent rereads. It does not overwrite. [inferred] That is the broker the collision note asks for. Validation and publication are one guarded step (`m3-agent-collisions.md:44`). A watcher is too late (`m1-prior-art.md:50`).

On weave, Kvarm does not union bytes. It runs three-way merge across admitted strands that share a base (`m2-kvarm-hooks.md:24`). Non-overlapping and identical line changes apply (`m2-kvarm-hooks.md:25`). Overlapping lines may try one bounded structural pass, and only where the grammar says order does not matter (`m1-prior-art.md:56`, `m2-kvarm-hooks.md:72`). Anything else becomes a durable conflict with both side blobs, not marker text in the file (`m1-prior-art.md:84`, `m2-kvarm-hooks.md:73`). [sourced] Jujutsu stores logical conflicts in commits (`m1-prior-art.md:84`). Loom stores them as strand pairs so the plant can pin them. [sourced] Pijul keeps both sides and says that does not guarantee meaning (`m1-prior-art.md:82`). Loom keeps both sides and refuses the implication. The hunk callback today returns only ours, theirs, or null (`m2-kvarm-hooks.md:72`), so the structural pass is a new versioned blob hook. Checks bind to its output, and they are never reused just because two strands looked disjoint (`m2-kvarm-hooks.md:82-83`).

Conflict, stale read, crash, and offline are different drawings (`CORE.md:95`, `01-synthesis-wave3.md:10`). A conflict pins both strands and ejects neither workspace. The losing strand stays recoverable. Today's resolver is whole-change and path-scoped (`m2-kvarm-hooks.md:29`). A stale read returns the anchor that moved, and the bot shows stopped rather than claimed (`CORE.md:83`). A crash drops the generation. A stored strand remains, and a new generation may withdraw it. Takeover waits for expiry, matching fencing (`m2-kvarm-hooks.md:78`). Offline strands queue locally and are not woven. Reconnect checks heads before send (`CORE.md:84`). [sourced] Kvarm has no local-first git fallback, so that queue is Orrery's until checkpoint (`m2-kvarm-hooks.md:93-94`). A push that skips admission cannot publish on a loom path. [inferred] A lease cannot prove the push stayed in a region (`m2-kvarm-hooks.md:81`). Replay is the proof.

**Safety.** [inferred] The published tree is one `treeSha`. Locked witnesses evaluate that sha and no other (`m2-kvarm-hooks.md:27`, `CORE.md:12`). Agents do not write those checks (`01-synthesis-wave3.md:9`, `01-synthesis-wave3.md:32`). A clean weave means the edits replayed and the checks passed. It does not mean both intents survived. [sourced] Structural merge is heuristic, and Mergiraf falls back to lines when parsing fails (`m1-prior-art.md:54`). [sourced] IntelliMerge's reported precision on its Java sample was 88.48 percent (`m1-prior-art.md:62`). [inferred] A green tree still hides a clash the witnesses do not cover. Brun's suites saw test failures beyond textual conflicts, and tests undercount (`m3-agent-collisions.md:56`). Each strand pair is marked excluded, woven, checked, or merely accepted (`m1-prior-art.md:173`). Merely accepted does not publish.

**Plant.** The file is a plate on the machine, not a terminal (`01-synthesis-wave3.md:11`, `01-synthesis-wave3.md:62`). Each strand is a footprint in the agent's colour, labeled with owner, generation, and source `declared` (`CORE.md:36`, `CORE.md:87`). A conflict is a brass pin. The verb is Settle (`CORE.md:35`). Shift 1 keeps the suggested side. Shift 2 keeps the other. Shift 3 splits the work into two orders. Shift 4 withdraws both. I jumps to the pin. The card shows both anchors, both read blobs, and the witness the weave would break. An arrival appends a footprint and toasts. It does not move the camera (`CORE.md:32`, `01-synthesis-wave3.md:19`). Unknown, stale, stopped, and conflicted stay distinct (`CORE.md:95`). One key, under ten seconds.

**Cost and slice.** [guess] Three to five weeks. Kvarm adds an admit op, a strand table, replay against `readBlob`, conflict rows richer than path and kind (`m2-kvarm-hooks.md:73`), and a weave step on the train. No CRDT. No per-keystroke writes (`m2-kvarm-hooks.md:86-87`). Structural weave stays behind a flag. Orrery draws footprints from `get_file_diff` until admit exists (`m2-kvarm-hooks.md:107-108`). The slice is two workspaces, one file, string replace only, publish only when locked checks pass on `treeSha`. Kill predicate, on a real repo. Both disjoint edits are present in the published blob. The planted overlap is a pin and does not publish. A strand against the wrong `readBlob` is rejected. A check naming any other sha fails the run. If a disjoint edit drops, or a conflict publishes, stop.

**Serves.** Disjoint regions in one cohesive file (`m3-agent-collisions.md:104`). Publication races between precise tools (`m3-agent-collisions.md:44`). Same-line syntax only when the structural flag applies and the grammar says order does not matter (`m3-agent-collisions.md:105`, `m1-prior-art.md:56`). **Routes elsewhere.** Keyed hotspots, which Stencil handles with less merge risk. Competing algorithms (`m3-agent-collisions.md:106`). Generated outputs (`m3-agent-collisions.md:108`).

## Mechanism C. Glass

**Pitch.** Put a CRDT under the file and require every harness write to enter it. Unfinished regions stay as holes so the program still has meaning. Publication is still a checked snapshot.

**Data shape.** A `Glass` is `{glassId, path, docId, snapshotBlob, revision, state}`. An op is `{opId, owner, generation, parentOps, kind, anchor, text, origin}`. The unit is the character operation. The anchor is a relative position (`m1-prior-art.md:28`, `m1-prior-art.md:42`). State is `live`, `checkpointing`, `published`.

**Protocol.** Every mutation must enter the op log, including shell writes and formatters (`m1-prior-art.md:48-50`). Agents do not do that today. Kvarm has no buffer authority for it (`m2-kvarm-hooks.md:74`, `m2-kvarm-hooks.md:94`). CodeCRDT claims by writing, waiting 50 milliseconds, and rereading (`m1-prior-art.md:132`). That is not a fence (`m1-prior-art.md:134`). Crash recovery there is a timeout, not a generation (`m1-prior-art.md:132`). Offline, text can converge while intent does not (`m1-prior-art.md:24`, `m2-kvarm-hooks.md:100`).

**Safety.** [sourced] The guarantee is replica agreement. It is not parse, tests, or both intents (`m1-prior-art.md:24`). [sourced] CodeCRDT's 600 trials ran from a 21.1 percent speedup to a 39.4 percent slowdown, with full text convergence and only a preliminary semantic-conflict estimate (`m1-prior-art.md:130`). [inferred] Hazel-style holes would keep a half-built file from poisoning the compiler (`m1-prior-art.md:106-108`). They are not a drop-in for TypeScript or Rust. [inferred] Glass also invites the repair loop, where one agent "fixes" another's unfinished edit (`m3-agent-collisions.md:46`). Making checkpoints the only readable surface recreates Loom on a harder transport.

**Plant.** Live cursors make the agent the subject. The plant is a canvas of systems (`01-synthesis-wave3.md:11`). A glass buffer fights that. Pins could mark conflicts, but moving characters read as false progress (`01-synthesis-wave3.md:65`).

**Cost and slice.** [guess] Six to twelve weeks before a credible pilot, matching the shared-buffer estimate (`m2-kvarm-hooks.md:74`). Kill predicate. One formatter or shell redirect outside the op log drops another agent's edit, and the safety claim is already false (`m3-agent-collisions.md:42`). **Serves** same-line syntax only, and only inside the op log (`m3-agent-collisions.md:105`). **Routes elsewhere** everything the harnesses actually do.

## Pick

[inferred] Pick Loom. Stencil is the better object when a key exists, and those clashes should route there, or to a split, before a loom opens (`m3-agent-collisions.md:102`, `m3-agent-collisions.md:121`). Glass answers a question the agents do not ask, with a guarantee the program does not need (`m1-prior-art.md:5`, `m1-prior-art.md:24`). Loom makes same-file work first-class for the tools Claude Code, Droid, and Codex already call, without a shared writable checkout and without treating convergence as correctness.

[inferred] It borrows the read-revision transaction from the prior-art gap (`m1-prior-art.md:9`, `m1-prior-art.md:169`). It borrows relative anchors from Yjs and leaves the character CRDT behind (`m1-prior-art.md:28`). It borrows retained conflicts from Jujutsu and Pijul (`m1-prior-art.md:82-84`), structural merge as a bounded fallback from Mergiraf (`m1-prior-art.md:54-56`), and fencing plus exact-tree checks from Kvarm (`m2-kvarm-hooks.md:27`, `m2-kvarm-hooks.md:78`). The plant language is CORE's. A pin, one settlement verb, a generation, and a stale or unmatched state that is never drawn as claimed (`CORE.md:5`, `CORE.md:15`, `CORE.md:82`).

[inferred] What is new is the strand. CodeCRDT shares a Yjs buffer and assigns TODOs after a delay (`m1-prior-art.md:128-132`). Mergiraf merges three snapshots and does not know which tool call, or which read blob, produced a side (`m1-prior-art.md:54`, `m1-prior-art.md:72`). Jujutsu stores conflicts in commits and does not promise two editors can overwrite one working file (`m1-prior-art.md:84-86`). Loom admits the tool call, keyed by the blob the agent read, weaves only admitted strands, and will not publish a tree whose checks name any other sha. The developer sees regions and pins, and settles a physical clash in one key.

[inferred] Two risks dominate. First, admission can be skipped. A shell write, a formatter, or a direct push that never becomes a strand recreates the lost update (`m3-agent-collisions.md:42-44`, `m2-kvarm-hooks.md:81`). If the slice cannot reject an unadmitted write on a loom path, do not ship the drawing. Second, a green weave can hide a semantic clash the witnesses do not mention. Structural tools already disagree with each other (`m1-prior-art.md:68`, `m3-agent-collisions.md:58`). Merely accepted stays off the published ref. Competing algorithms go back to the belt (`m3-agent-collisions.md:106`). If overlaps publish, or checks bind to the wrong tree, the mechanism fails closed and stays off.
