# Proposed map amendments from the agentic UX work (ui-v2)

`map.md` stays the source of truth and is not edited here. Each row below is written in map.md's own format, so it can be pasted in as is. Rows marked **amends** add an "→ amended by" note to the named entry. This proposal follows `proposals/ui-v1.md` and assumes its V rows are accepted.

The work targets the two pains the user named. The first is turning intent into instructions agents follow. The second is coordinating many agents at once. The plant metaphor stays. What changes is how work reaches agents, how agents settle shared ground, and where coordination state lives.

Two prefixes are used. **C** rows are the four concepts the user chose to prototype (orders, clash, gate, bench). **W** rows are the wave-3 rows (Kvarm, dogfood, fidelity, world, appearance), numbered as in the wave-3 synthesis candidate table, with W20 to W22 added. W23 to W27 are the same-file co-editing rows, added after the history replay.

Evidence labels: **user** means the user decided it in an interview round. **seen** means read in a source file or observed in a prototype this session. **inferred** means reasoned from that. **guess** means neither.

Source keys: `dec` is `research/agentic-ux/decisions.tsv`, `syn` is `research/agentic-ux/00-synthesis.md`, `judge` is `research/agentic-ux/concepts/00-judging.md`, `w3` is `research/agentic-ux/01-synthesis-wave3.md`, `h`, `i`, `j` and `l` are `research/agentic-ux/h-kvarm.md`, `i-dogfood-droid.md`, `j-plant-fidelity.md` and `l-light-mode.md`, `CORE` is `ui-v2/CORE.md`, `sfj` is `research/agentic-ux/same-file/00-judging.md`, `m2`, `m3` and `m4` are `research/agentic-ux/same-file/m2-kvarm-hooks.md`, `m3-agent-collisions.md` and `m4-replay-results.md`, and `map` is `map.md`.

## Open validation work

- **Deployed Kvarm behavior.** Kvarm was read at `c80253b` without a deployed origin [seen, dec:19]. Token permissions in a real account, live latency and end-to-end reconnect are unconfirmed [seen, h:253]. Full operation needs Cloudflare services [seen, h:184].

- **Other Kvarm gaps.** Witness objects, readback-gated claims (W20), read-blob admission (W25, sfj:33), path protection, idempotency keys, local evidence references and design-only scopes are requests, not features [seen, h:224-240].

- **Solo-owner approval.** Whether one human can approve agent work that Kvarm attributes to a principal they minted [seen, h:151-152].
- **A6 level names.** Not specified anywhere [seen, h:198, h:255].
- **Windows.** The WSL2 write path is untested. Droid and Codex session paths on Windows are still inferred [seen, map:309].
- **Display limits.** All binding count limits and the five-second stale threshold are guesses [seen, j:209, j:248].
- **Rendered contrast.** Only swatch arithmetic is done. Glass composites, thin strokes, CVD, grayscale and real displays are open [seen, l:286-290, dec:30].
- **User tests.** Every kill test is a user study, and none can run in this session [seen, judge:37]. Readback match rates, review-minute estimates and clash precision are guesses [seen, judge:38]. No source measures how many agents one person can supervise [seen, syn:115].

## What the prototypes prove and do not prove

All numbers in the prototypes are scripted fixtures [seen, judge:37]. Each concept is driven by `node drive.mjs` with keyboard and mouse paths. The stock build and drive for orders, clash and world passed with zero page errors after their fix rounds [seen, dec:40].

**`live-orders.html#c=orders&mode=replay`** (also `&t=<sec>&sel=<id>`). It proves the pin, post, readback, question, answer and self-claim flow works from the keyboard and the mouse, and that later agent events never steal focus [seen, CORE:30, dec:40]. After the fix round, disagreement and claim read clearly [seen, dec:41]. It does not prove readbacks are useful, that agents would interpret orders this way, or anything about Kvarm. The `kv=` fixture flags (W2, W4, W5) were not in `orders.mjs` when this was written [seen, by search]. A Kvarm pass is still running [seen, dec:42].

**`live-clash.html#c=clash`.** It proves all settlement kinds, undo, reopen and Esc can be done before code, and the consequence leads the card after the fix round [seen, dec:29, dec:41]. It does not prove declarations can be collected from real agents, clash precision, or Kvarm forecast and `record_decision` behavior. Those flags are also pending [seen, by search].

**`live-world.html#c=world`**, with `&theme=light` and `&kv=offline`. It proves stable site coordinates across jumps, history and search [seen, world.steps.json:111, :128]. It draws the five evidence states from binding records [seen, world-data.mjs:12-16] and opens a provenance popover. F8 keeps camera and selection [seen, world.steps.json:71-73]. Offline shows stale fields and pending writes. It does not prove the world scales past five plants, meets A10, or reads at second-monitor distance. Known issues are four look-alike plant slabs, marketing hero copy, a lingering toast and a minimap label collision [seen, dec:41]. Light screenshots look drafted [seen, dec:41], but rendered contrast is not measured.

**Gate and bench.** At the time of writing, `concepts/gate.mjs` and `concepts/bench.mjs` are empty stubs, and `live-gate.html` was built from the stub [seen]. Builds are in progress [seen, dec:42]. They prove nothing yet, so C3 and C4 rest on research and the user's decisions only.
